# Amazon S3 objects

Reads CSV, TSV, JSON, JSONL or Parquet objects from an S3 bucket (or an S3-compatible store) into reviewed local snapshots. One connection names the bucket and credentials; each table names an object or prefix and its format. Requests are signed with AWS Signature Version 4 using the Python standard library; nothing is written.

| Package  | `s3@1.0.0`                                                                       |
| -------- | -------------------------------------------------------------------------------- |
| Kind     | `s3`                                                                             |
| Maturity | verified: conformance suite against an S3-compatible server in a local container |
| Licence  | Adapter Apache-2.0; upstream pyarrow Apache-2.0                                  |
| Cost     | No Ingestron charge; S3 request and transfer charges apply                       |

## Install

```sh
ingestron connector install s3@1.0.0
```

## Connection

Use an access key with `s3:ListBucket` on the bucket and `s3:GetObject` on the objects. Keep the secret (and any session token) in environment variables referenced with `$secret`. For S3-compatible stores set `endpoint` (HTTPS; HTTP only for a loopback test server).

```yaml
connections:
  source:
    package: s3
    sourceId: source
    tenantId: training
    settings:
      bucket: retail-exports
      region: ap-southeast-2
      access_key_id: AKIAEXAMPLE
      secret_access_key:
        $secret:
          env: AWS_SECRET_ACCESS_KEY
flows:
  - apiVersion: ingestron.flow/v1
    kind: ingestion
    id: source_local
    provider: local
    ingestion:
      connection: source
      execution: { mode: local }
    tables:
      customers:
        source: { path: v1/customers.csv, format: csv }
        contract: { $resolve: ./contracts/customers.odcs.yaml }
      orders:
        source: { path: v1/orders, format: parquet }
        contract: { $resolve: ./contracts/orders.odcs.yaml }
```

## Tables

| `source` key | Meaning                                                                                                             |
| ------------ | ------------------------------------------------------------------------------------------------------------------- |
| `path`       | Object key (or file path) to read one file, or a prefix (folder) to read every file of the format directly under it |
| `format`     | `csv`, `tsv`, `json`, `jsonl` or `parquet`                                                                          |

A prefix is one table: its files are read in name order and must share one
schema. Up to 100 files per prefix and 64 MiB per file.

## Types

Types come from each table's contract, as for [local files](files.md): string, integer, decimal, number and boolean.

## Behaviour and limits

Listing uses ListObjectsV2 with a delimiter, so subfolders are not read. Each object is downloaded, its length checked against the listing, parsed and removed. Every selected table is read before any record is committed. Errors name a code (`S3_AUTH`, `S3_FORBIDDEN`, `S3_NOT_FOUND`, `S3_NO_FILES`, `S3_CHANGED`, `S3_SCHEMA`, `S3_NETWORK` and others) and never include keys or file contents.

## Evidence

The shared conformance suite passes against an in-memory S3 API and against SeaweedFS in a local container, which verifies every SigV4 signature (`pnpm test:containers`). The signer also reproduces the AWS documented example signature. It has not yet been run against AWS itself.
